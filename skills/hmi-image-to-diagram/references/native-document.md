# 原生图纸批量载入

当同类管段、读数框或按钮较多，且指定编辑器能导入或载入原生图纸时，可用参考图坐标表生成原生模型。小改动通常直接在画布上做。接口不可用、版本对不上或无法完成小批往返验证时，改用编辑器界面。

准备按坐标表生成原生图元时，使用技能内的 `scripts/build_native_document.py`。输入格式、模板复用、累积批次和回归数据见 [批量生成脚本](batch-script.md)。

## 用当前版本的样件确定格式

1. 从同版本编辑器导出或读取一小组原生样件，覆盖本图用到的折线管道、仪表虚线、文字、渐变图形、组合和按钮。已有导出件可以用于识别格式，先和当前版本的小样比较。若在目标图纸上临时试画，记录试验件并在保存正式批次前清理，保留基线图元及用户未保存的编辑。确认画幅用的是图纸尺寸，并核对坐标原点、尺寸与缩放、图层及组合关系。
2. 记录目标图纸的项目、路径或编码。修订已有图纸时，以目标图纸的模型为底稿，保留范围之外的原有图元、图层、图纸属性及业务配置。生成新图时从样件提取图元的结构和样式，目标图纸的身份与配置取自目标本身。
3. 用短数据表生成分批模型，并以小批试载入、保存、回读验证。区分接口是追加图元还是整图重建。整图重建时，每批模型应包含已验收的前批、原有内容和本批增量。对跨批不变的图元复用标识，新图元用唯一标识，组合引用指向本图纸的父件。先查清基线已有的数据和当前未保存的改动，再重建画布。

## 保留可续作的批次

- 开始批量载入前，在任务的临时工作目录保留原始底稿、场景表及当前批次的输出。先落盘再载入，浏览器脚本会话消失后仍能重建。另记项目、图纸路径、编码、最近已确认的批次和图元数。待确认批次保留其输出及请求标识，便于回读对照。
- 恢复时先核对目标和已保存内容。上一批已落盘时从下一批继续，尚未落盘时复用保留的批次文件与原标识。若回读发现额外编辑，先确认差异并保留范围外的改动。已生成的图元有冲突时，解决冲突后再重建。详见 [会话中断后续作](editor-workflow.md#会话中断后续作)。

## 浏览器 HMI 编辑器实测

以下字段和方法是总流程图案例的版本线索，需在当前编辑器用样件复核。优先用产品提供的导入入口或原生模型接口。有些版本只显示导出。仅在当前工具允许且该版本确实暴露应用自身模型接口时，才通过该接口载入。

| 项目 | 已验证的格式或行为 |
| --- | --- |
| 图纸模型 | 根对象为 `document`，图元在 `document.elements`。画幅及背景取自 `pageProperty`。样件同时含 `width/height` 和 `pageWidth/pageHeight`，生成新画幅时保持两对值一致。 |
| 管道 | `Pipeline.polygon` 保存有序折点。参考样件的虚线用底层描边 `bgStroke`、`bgStrokeWidth`、`bgDash` 和 `borderStyle: 2`，关闭前景线 `fgEnabled`，再检查虚线间隙。 |
| 文字与组合 | `Text.text` 使用 UTF-8 的 Base64 编码。编辑器旋转 90° 的样件同时写入 `roateAngle`、旋转后的 `localRect` 四角和中心 `roatePos`，宽高仍为旋转前的值。组合以 `pId` 指向父件 `id`，子件坐标沿用图纸坐标，在组内校对叠放顺序。 |
| 原生按钮 | 样件为按钮库的 `NodeSymbol`，带 `hmi.type: Button`。复用样件的库路径与基础尺寸。在 `dataBind` 设置 `button.text` 和 `button.text.pressed`。若要匹配高亮导航样式，可对照样件的 `button.background.default`。等图符加载完成、按钮可见且两态文字确认后再保存。 |
| 模型载入 | 用 `window.__hmi_editor.tabs.current` 获取当前图纸，以 `core.data` 核对身份。`editor.dataManager.deserialize(jsonText)` 会重建画布，`core.graphView.toJson()` 可回读。调用前在画布空白处取消选中。3# 产线案例中，临时图元仍选中时重建报错，随后回读也失败。若出现这种状态，先核对已保存和未保存的内容，必要时重开同一图纸再载入。若重建后仅 `document.code` 被清空且资源身份吻合，该版本可用 `core.graphView.stage.setStore('code', originalCode)` 恢复原编码，再回读确认。身份有其他差异时暂缓保存。 |
| 保存回执 | 通过编辑器的“保存”提交。图纸 JSON 和缩略图各有一笔 `update` 与独立的 `operationDone`。若工具支持观察回执，从保存前记录的观察位置向后查找，用图纸路径及请求标识匹配 JSON 回执并检查成功状态。若首次只看到发送记录，继续观察同一请求，必要时回读图纸。缩略图成功、按钮可见或回执暂未返回，都不足以判定图纸写入结果。 |

导入成功后先检查画布首末件、关键接点和异步按钮。在最后一批保存成功后回读同一资源，抽查图元类型、组合关系、两态按钮文字及画幅。若回读与预期不符，先区分未载入、未保存和保存到其他资源，再决定如何恢复。
