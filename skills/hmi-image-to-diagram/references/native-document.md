# 原生图纸批量载入

当同类管段、读数框或按钮较多，且指定编辑器能导入或载入原生图纸时，可用参考图坐标表生成原生模型。小改动通常直接在画布上做。接口不可用、版本对不上或无法完成小批往返验证时，改用编辑器界面。

准备按坐标表生成原生图元时，使用技能内的 `scripts/build_native_document.py`。输入格式、模板复用、累积批次和回归数据见 [批量生成脚本](batch-script.md)。

## 用当前版本的样件确定格式

1. 从同版本编辑器导出或读取一小组原生样件，覆盖折线管道、仪表虚线、文字、渐变图形、组合和按钮。已有导出件可以用于识别格式，先和当前版本的小样比较。确认画幅用的是图纸尺寸，并核对坐标原点、尺寸与缩放、图层及组合关系。
2. 记录目标图纸的项目、路径或编码。修订已有图纸时，以目标图纸的模型为底稿，保留范围之外的原有图元、图层、图纸属性及业务配置。生成新图时从样件提取图元的结构和样式，目标图纸的身份与配置取自目标本身。
3. 用短数据表生成分批模型，并以小批试载入、保存、回读验证。区分接口是追加图元还是整图重建。整图重建时，每批模型应包含已验收的前批、原有内容和本批增量。对跨批不变的图元复用标识，新图元用唯一标识，组合引用指向本图纸的父件。先查清基线已有的数据和当前未保存的改动，再重建画布。

## 浏览器 HMI 编辑器实测

以下字段和方法是总流程图案例的版本线索，需在当前编辑器用样件复核。优先用产品提供的导入入口或原生模型接口。有些版本只显示导出。仅在当前工具允许且该版本确实暴露应用自身模型接口时，才通过该接口载入。

| 项目 | 已验证的格式或行为 |
| --- | --- |
| 图纸模型 | 根对象为 `document`，图元在 `document.elements`。画幅及背景取自 `pageProperty`。样件同时含 `width/height` 和 `pageWidth/pageHeight`，生成新画幅时保持两对值一致。 |
| 管道、文字、组合 | `Pipeline.polygon` 保存有序折点，管线底描边及虚线分别见 `bgStroke`、`bgStrokeWidth`、`bgDash`。分别对照实线和虚线样件，避免前景实线盖住虚线。该版本 `Text.text` 使用 UTF-8 的 Base64 编码。组合以 `pId` 指向父件的 `id`，子件坐标沿用图纸坐标，在组内校对叠放顺序。 |
| 原生按钮 | 样件为按钮库的 `NodeSymbol`，带 `hmi.type: Button`。复用样件的库路径与基础尺寸，在 `dataBind` 设置 `button.text` 和 `button.text.pressed`。载入后按钮库图符可能异步出现，等按钮可见且类型和数量稳定后再保存。 |
| 模型载入 | 该版本在 `window.__hmi_editor.tabs.current` 提供当前图纸，`core.data` 可核对资源身份，`editor.dataManager.deserialize(jsonText)` 会重建画布，`core.graphView.toJson()` 可回读。载入曾清空画布模型的 `document.code`。若仅此字段被清空，且已确认仍为同一资源，该版本用 `core.graphView.stage.setStore('code', originalCode)` 恢复已记录的原编码，再回读确认。身份字段出现其他差异时先排查并暂缓保存。 |
| 保存回执 | 通过编辑器的“保存”提交。实测缩略图和图纸 JSON 分别提交 `update`，各有独立的 `operationDone` 回执。若通过工具观察回执，按请求标识匹配目标图纸 JSON，检查路径和成功状态。单独的缩略图成功不足以证明图元保存。 |

导入成功后先检查画布首末件、关键接点和异步按钮。在最后一批保存成功后回读同一资源，抽查图元类型、组合关系、两态按钮文字及画幅。若回读与预期不符，先区分未载入、未保存和保存到其他资源，再决定如何恢复。
